# 濫用情境

- 版本：Day 1 初版（2026-11-26）。
- 用法：每一條都是之後某一天要寫成自動化測試的情境，測試放在 `test/abuse/`。測試要證明的是「攻擊者這樣做時會被擋下」，所以每條都寫了預期的結果。
- 邊界代號（B1–B5）與缺口代號（G-1–G-8）見 [threat-model.md](threat-model.md)；S-xx 見 [SECURITY-REVIEW.md](../SECURITY-REVIEW.md)。
- 這份清單會長大。每天做到新功能時，從威脅模型裡「不夠」的格子補新的條目進來。

## 每條的預期結果

寫測試時以這裡為準。寫的是重寫後應有的行為，不是 SPEC 目前的行為。

**A-01** 沒設 `ADMIN_PASSWORD` 時不存在預設帳號，admin／admin 登入回 401。`GET /api/health` 的回應在設定前後完全相同，只有 `{ ok: true }`。設定完成前 `POST /api/join` 回 403。

**A-02** 未登入的人送錯配對碼，只影響自己這個 IP 的額度，別人已產生的配對碼仍然可用。對某帳號連續打錯密碼後，帳號的主人從另一個 IP 用正確密碼仍然登得進去。

**A-03** 每一條路徑都回 404，而且回應的內容、狀態碼與「這個 ID 根本不存在」時相同，不能從差異推出卡片存在。搜尋結果不含專案 B 的任何一筆。

**A-04** 改別人的卡回 403 `NOT_CARD_OWNER`；建卡指定別人回 403 `ASSIGN_OTHERS`；自己完成的卡自己驗證回 403 `SELF_VERIFY`。三者都不改變卡片的 `version`。

**A-05** 重設登入要求管理員在近期重新驗證過身分，沒有就拒絕。每次重設都寫入稽核紀錄，並留一則安全通知給被重設的成員，他下次登入時看得到。管理員直接對決策卡 `decide` 回 403 `NOT_DECIDER`。這三項擋不住管理員用連結冒用成員，只讓這件事事後查得到。要真的擋住，連結必須走管理員碰不到的管道，而 SPEC 沒有這種管道；Day 6 決定做法後回來補這條的斷言。

**A-06** 密碼雜湊的格式帶有演算法與參數，參數不低於當時的設定值（測試讀設定值比對，不寫死數字）。用資料庫裡的 Token 雜湊簽出來的門鈴，watcher 仍會用自己的 Token 向伺服器確認，沒有待處理事項就不叫醒 AI。

**A-07** 腳本內容與簽章不符時，setup 拒絕執行並保留原檔，不自動下載覆蓋。平台網址不是本機位址又是 `http://` 時，腳本拒絕連線。有新版時只通知所屬人類，不自行更新。

**A-08** 對接入連結發 GET（含 HEAD）不換發 Token，原本的 Token 仍然有效。換發只接受 POST，代碼放在請求本文；同一個代碼用第二次回 410。

**A-09** 一般成員上傳的純文件技能狀態是 `pending`，在 leader 或管理員核准前，`GET /api/me/skills` 對任何 AI 都不回這份技能。核准後，在 AI 的主人允許這一版之前仍然不回。上傳者自己核准回 403 `SELF_REVIEW`。

**A-10** AI 的 GET 回應中，`blocker`、`criteria`、成員名稱、專案名稱、檔名都被標為不可信；下載的檔案內容也是。本機的 hook 在沒有人類確認時擋下 `git push` 與部署指令，不論模型怎麼判斷。這條的前半可以自動化；「模型不照指令做」無法用測試保證，測試只驗證標記存在與 hook 擋得住。

## 還沒列進來、之後要補的方向

- 偽造 `X-Forwarded-For` 繞過以 IP 為單位的限流（S-11，Day 8）。
- 註冊大量帳號佔滿即時連線（S-13，Day 23）。
- 同機其他使用者讀 `.aigile/<代號>/.token`（S-14，Day 24）。
- 唯讀成員透過名下 AI 在唯讀專案寫入（§6.1，Day 9）。
- 一段假的接入文字把 AI 指向攻擊者的伺服器（G-3，Day 25）。
- 兩隻 AI 互相回覆形成迴圈（G-7，Day 22）。
